# Safety model

**The owner alone decides and performs manual cleanup in their file manager.** Hibernator and its Agent Skill read the project, save private reports outside it, and stop. The compatibility apply command refuses immediately without reading a plan, prompting or mutating project files. Approval phrases have no authority.

## What retirement protects

- One canonical local Git root. Root and ancestors must be unaliased. Git administrative files, linked worktrees, unsupported indexes and submodule arrangements fail closed.
- Tracked and staged-deletion prefixes, missing tracked entries, local changes, secret-like names, databases, uploaded data, original assets and unknown files.
- Candidate descendants. Links, reparse points, hard links, filesystem crossings, nested Git boundaries, inaccessible entries and unknown payloads disqualify the containing artifact. Protected parents suppress child suggestions.
- Reports use a validated outside directory and unique private run directories. POSIX report files are owner-only. Windows access follows local ACLs and report directory handles are held during publication.

## Observation limits

Git subprocesses use explicit local command vectors, timeouts and a stripped Git environment. Retirement reads the tracked index and HEAD tree without running worktree status or hashing source and secret files. Manifest and lockfile reads are bounded and names that look like secrets are preserved without opening their contents. Installer commands, filters and project imports are outside this workflow.

The inventory observes metadata and optionally hashes eligible payloads. It checks root, Git, evidence and candidate-root stamps at the end. These operations are path observations during an interval. Concurrent edits, platform-specific mounts and replacements can escape a targeted check. Linux uses visible mount boundaries, including entries listed as same-device, and other platforms have different coverage. Pause builds and re-run after relevant changes. `KEEP`, `REVIEW` and `BLOCKED` entries stay outside the manual list.

Logical byte estimates sum regular file lengths. Allocation, compression, snapshots, Recycle Bin, Trash and unrelated activity affect real free space. Hibernator did not modify project files. Actual bytes reclaimed by Hibernator: 0.
